# CareLoop 安步：專案專有名詞與操作解析百科
# Glossary & Operations Guide

本文件旨在為新加入的團隊成員、開發者以及未來接手專案的人員，提供 CareLoop 系統內所有「專有名詞」、「技術術語」與「系統操作機制」的完整、白話解析。

---

## 1. 核心臨床與測試名詞

### FTSST (Five Times Sit-to-Stand Test)
- **中文**：五次坐站測試
- **定義**：一種廣泛使用於老年醫學與物理治療的臨床測試。受測者雙手抱胸，從有靠背的椅子上盡快起立並坐下，連續完成五次。
- **在專案中的角色**：CareLoop 系統「唯一」支援的動作觀察框架。所有計時、次數與偏移閾值皆針對此測試設計。
- **引用來源**：Bohannon (2006) 確立的常態值。

### 參數一致性測試 (Parameter Consistency Test)
- **中文**：參數一致性測試
- **定義**：為彌補「缺乏真實受試者資料」而設計的軟體驗證方法。系統使用蒙地卡羅方法（Monte Carlo）隨機生成符合真實年齡分佈（如：70歲以上長輩耗時分佈）的假資料（合成患者），然後將 CareLoop 決策引擎的判斷結果，與原發表的醫學文獻進行比對。
- **在專案中的角色**：這是用來證明「程式邏輯沒寫錯」，**並非**宣稱系統有醫療診斷能力的外部驗證。
- **注意**：v2.0 嚴格禁止稱此為「FDA 認可的 In Silico Validation」。

### Expert Agreement Study
- **中文**：專家一致性研究
- **定義**：讓實體的「物理治療師」盲測（不知道 AI 怎麼判斷），看影片對長輩動作給出評估，然後拿專家的答案跟 CareLoop AI 的答案進行統計比對。
- **在專案中的角色**：這是團隊「下一階段」的目標，目前尚未執行。用來計算 ICC（組內相關係數）。

## 2. 系統狀態與資料名詞

### ObservationLevel
- **中文**：觀察等級
- **定義**：CareLoop 系統輸出給使用者的最終評估狀態。
- **三個嚴格定義的值**：
  1. `smooth`（動作順暢）：無明顯偏移訊號。
  2. `attention`（略有偏移）：輕度偏移，建議家人留意。
  3. `review`（建議家人確認）：明顯偏移或晃動，建議確認。
- **注意**：嚴禁使用已棄用的舊名詞（stable / unstable / risk / high-risk / low / medium）。

### SessionEvent
- **中文**：測試紀錄物件
- **定義**：存在 `localStorage` 中的單筆 JSON 資料結構。包含 `id`, `date`, `durationSec`, `tiltMaxDeg`, `instabilityEvents`, `level` 等數據。

## 3. 核心技術與演算法名詞

### MediaPipe Pose Landmarker
- **中文**：MediaPipe 姿態標記器
- **定義**：由 Google 開發的開源模型，能從影像中找出人體的 33 個骨架關鍵點（Keypoints）。
- **在專案中的角色**：作為「感知層（Perception）」的視覺基底。它完全在瀏覽器本機的 WASM 環境中執行，不傳送影像到後端。

### 雙模態感測器融合 (Sensor Fusion)
- **中文**：感測器融合
- **定義**：不僅依賴「鏡頭（視覺）」，還結合手機內建的「陀螺儀與加速度計（慣性，DeviceMotionEvent）」。
- **為什麼需要？**：因為長輩家中光線可能不好，單靠鏡頭容易算錯。結合手機本身的物理晃動數據，能提高「晃動事件（Instability）」判定準確率。

### SNR 加權互補濾波器 (SNR-Weighted Complementary Filter)
- **中文**：訊噪比加權互補濾波器
- **定義**：融合上述「視覺」與「慣性」兩組數據的數學方法。
- **運作原理**：如果鏡頭畫面變暗（視覺 SNR 下降），系統就會自動增加「陀螺儀數據」在計算中的權重。反之亦然。這是 `lib/sensor-fusion.ts` 的核心。

### 個人化自適應基準線 (Adaptive Baseline)
- **中文**：個人化自適應基準線
- **定義**：系統不只看「絕對的臨床標準」（例如：大於 3.34 秒算慢），還會看「使用者自己的近期平均標準」（例如：某位使用者平常就要 4 秒，今天 4.1 秒對他來說可能仍在正常波動內）。
- **運作原理**：收集至少 3 筆可用歷史資料後，計算該使用者的均值（Mean）與標準差（SD）。如果當天表現超出 `均值 + 2個標準差`，才會觸發額外的留意提示（實作於 `lib/adaptive-baseline.ts`）。

## 4. 系統防呆與容錯機制 (Operations & Fallbacks)

### Privacy by Constraint
- **中文**：受限隱私設計
- **定義**：因為團隊沒錢買雲端伺服器，所有資料「只能」存在手機本機（localStorage）。但我們把這個劣勢轉化為優勢：這保證了長輩的隱私絕對不會外洩。

### GPU Fallback
- **中文**：GPU 降級機制
- **定義**：MediaPipe 預設嘗試用手機的 GPU 來算骨架。如果使用者的手機太舊，或是瀏覽器不支援 WebGL，系統不會直接當機白屏，而是會 `try-catch` 捕捉錯誤，自動切換回「CPU 模式」繼續運算（實作於 `components/PoseCanvas.tsx`）。

### localStorage QuotaExceededError
- **中文**：儲存空間超載保護
- **定義**：瀏覽器的 `localStorage` 容量通常只有 5MB。如果長輩天天測，幾年後資料滿了，寫入時會報錯（QuotaExceededError）。
- **應對機制**：系統在 `lib/storage.ts` 中設計了攔截機制。如果滿了，會自動刪除最舊的資料，永遠保留最新的 20 筆。

### Demo 防線 (Fallback Data)
- **中文**：展示防線
- **定義**：在評審現場 Demo 時，如果遇到「網路全斷」、「攝影機權限卡死被拒絕」等致命情況，應用程式會顯示一個【使用示範資料】按鈕。
- **運作原理**：點擊後會直接載入 `public/demo-sessions.json` 的假資料，讓團隊還是能順利向評審展示「家屬問答」、「歷史趨勢圖」等功能，不會因為硬體卡關而 0 分出局。

## 5. 常見操作指令 (CLI Commands)

這些指令在開發與修復過程中非常重要，請務必熟記：

- `npx eslint .`：執行靜態語法檢查，必須確保 0 errors, 0 warnings。
- `npx tsc --noEmit`：執行 TypeScript 型別檢查，確保不會有 `any` 造成的潛在當機。
- `npm run dev`：啟動本地開發伺服器（需透過 localhost 或 https，否則相機無法開啟）。
- `npm run build`：生產環境建置。這會確保所有 9 個頁面都能成功打包為靜態網頁（Static Pages）。
